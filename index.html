Chương 1

Tổng quan Tự động hóa Thiết kế Vi mạch (IC Design Automation)

1. Quy trình thiết kế vi mạch (IC Design Flow)

🔹 Frontend (Thiết kế mức hàm & logic)
  • RTL Design: Viết mã phần cứng bằng Verilog / VHDL / SystemVerilog.
  • Functional Verification: Mô phỏng kiểm tra chức năng logic bằng testbench.
  • Synthesis: Tổng hợp RTL sang cổng logic thực tế (Gate-level netlist).
🔹 Backend (Thiết kế vật lý - Physical Design)
  • Floorplanning & Placement: Quy hoạch diện tích die và định vị hàng triệu cell logic.
  • Clock Tree Synthesis (CTS): Xây dựng mạng cây phân phối xung nhịp cân bằng độ trễ.
  • Routing & Signoff: Đi dây kết nối kim loại, kiểm tra quy tắc vật lý DRC/LVS và ký duyệt.

2. Hạn chế của GUI & Tư duy Script-First

GUI rất tốt để trực quan hóa, nhưng trong công nghiệp vi mạch có các nhược điểm chí mạng:

  • Non-reproducible: Không thể tái lập lại chính xác chuỗi thao tác chuột.
  • Không mở rộng: Không thể click tay cho 1.000 test case.
  • Không tích hợp CI/CD: Máy chủ tự động không thể dùng chuột.
⭐ Quy tắc vàng: Làm việc nhiều hơn 2 lần ➔ Viết script!

3. Kiểm thử hồi quy (Regression Testing)

Chạy lại toàn bộ tập hợp test sau mỗi lần sửa đổi mã thiết kế hoặc cập nhật công cụ EDA:

  • Phát hiện lỗi sớm ngay khi code bị hồi quy (regression).
  • Đảm bảo chất lượng sản phẩm sau mỗi commit mã nguồn.
  • Tập hợp test case chính là tài liệu sống của dự án.
  • Thực tế công nghiệp: chạy > 100.000 test cases mỗi ngày trên hệ thống cluster.

Làm Việc với Shell Bash trong Môi Trường Linux

1. Cấu trúc Project chuẩn trong IC Design

rtl/ tb/ sim/ synth/ reports/ scripts/ Makefile
  • /opt/synopsys/, /opt/cadence/: Đường dẫn cài đặt công cụ EDA.
  • ~/: Thư mục cá nhân của kỹ sư (Home directory).
  • pwd, cd, ls -la, mkdir -p, cp -r, mv, rm -i, ln -s: Các lệnh điều hướng bắt buộc.

2. Phân quyền tập tin (Permissions rwx)

  • chmod +x script.sh hoặc chmod 755 script.sh: Bắt buộc cấp quyền thực thi cho file kịch bản.
  • chmod 644 report.txt: Quyền đọc ghi cho chủ sở hữu, người khác chỉ đọc.
  • ls -l: Kiểm tra chi tiết 10 bit quyền của file.
📌 Best practice: Kịch bản automation luôn cần chmod +x. Tool thực thi cần 755.

3. Pipe và Điều hướng dòng dữ liệu (Pipes & Redirection)

dc_shell -f run.tcl > log.txt 2>&1

Gộp cả kết quả chuẩn (stdout - 1) và thông báo lỗi (stderr - 2) vào file log.

grep VIOLATION *.rpt | head -10

Lọc các dòng có từ VIOLATION và chỉ lấy 10 dòng đầu tiên.

⭐ Best practices cho Bash Scripting trong sản xuất:

1. Luôn bắt đầu bằng shebang: #!/bin/bash

2. Luôn đặt cờ: set -euo pipefail ở đầu file để script tự dừng khi có lệnh lỗi hoặc gọi biến chưa khai báo.

3. Vòng lặp đọc log an toàn: while IFS= read -r line; do ... done < log.txt

Chương 3

Cú Pháp Tcl và Cấu Trúc Dữ Liệu Cơ Bản

1. Cơ chế Tcl Interpreter & 3 loại Substitution

Trong Tcl: Mọi thứ đều là String và Mọi thứ đều là Command có dạng: command arg1 arg2...

1. Biến $

Thay thế giá trị của biến.

puts $name
2. Lệnh [...]

Thực thi lệnh lồng nhau.

set r [expr 2+3]
3. Backslash \

Ký tự đặc biệt hoặc nối dòng.

puts "A\nB"

2. Quy Tắc Then Chốt: Ngoặc Kép "" so với Ngoặc Nhọn {}

Double Quotes "" (CÓ substitution)

Dùng khi cần thay thế biến hoặc thực thi lệnh con lồng bên trong.

set g1 "Hello $name" ;# -> Hello World set g2 "2+3=[expr 2+3]" ;# -> 2+3=5
Braces {} (GIỮ NGUYÊN VĂN)

Vô hiệu hóa toàn bộ substitution. Bắt buộc dùng cho thân proc, if, while.

set g3 {Hello $name} ;# -> Hello $name expr {$a + $b} ;# Nhanh & chống double-sub
⚠️ Cảnh báo EDA: Lệnh create_clock -period $clock_period [get_ports clk] là ĐÚNG. Nếu bạn viết {$clock_period}, tool sẽ nhận nguyên chuỗi chữ "$clock_period" và báo lỗi cú pháp!

3. Thao tác với List trong Tcl

Cực kỳ quan trọng vì các lệnh EDA luôn trả về list các cells, pins, ports, nets:

  • lindex $list 0: Phần tử đầu tiên (index 0).
  • lindex $list end: Phần tử cuối cùng.
  • llength $list: Đếm số phần tử.
  • lsearch $list "item": Tìm vị trí (trả về -1 nếu không có).
  • lsort -integer -decreasing $list: Sắp xếp số giảm dần.

4. Thao tác với Array (Associative Array)

Mảng trong Tcl là mảng kết hợp theo cặp Key - Value (không phải mảng chỉ số như C):

  • array set power {adder 2.8 mult 9.3}
  • array names power: Trả về danh sách tất cả các key.
  • set matrix(0,1) 5: Giả lập mảng đa chiều bằng quy ước phân tách dấu phẩy.

Điều Khiển Luồng và Thủ Tục trong Tcl

1. Cấu trúc if / elseif / else

Cả biểu thức điều kiện và thân code block bắt buộc phải dùng cặp ngoặc nhọn {}:

if {$slack < 0} {
puts "ERROR: Timing violation"
} elseif {$slack < 0.2} {
puts "WARNING: Marginal"
} else {
puts "OK: Timing met"
}

2. Lệnh rẽ nhánh switch

Hỗ trợ các tùy chọn so khớp: -exact (mặc định), -glob, -regexp, -nocase:

switch -glob $filename {
"*.v" - "*.sv" { puts "HDL Source" }
"*.sdc" { puts "Constraint" }
default { puts "Unknown" }
}

Dấu gạch nối - ở đuôi pattern cho phép nhiều mẫu cùng chung một hành động.

Vòng lặp foreach

Vòng lặp quan trọng nhất trong EDA, duyệt danh sách, cặp key-value, duyệt mảng:

foreach m $mods { ... } foreach {k v} $list { ... }
Thủ tục & Scope

Biến trong proc mặc định là local:

• global <var>: Dùng biến toàn cục.

• upvar $name ref: Truyền tham chiếu (sửa biến gọi). Chú ý truyền tên biến, không truyền $.

Bắt lỗi an toàn với catch

Bắt lỗi runtime, tránh script dừng đột ngột:

if {[catch {open "f.txt" r} fid]} {
  puts "Lỗi: $fid"
}

Xử Lý Chuỗi, Biểu Thức Chính Quy và File I/O trong Tcl

1. Thao tác Chuỗi (string) cơ bản

  • string length "Hello" ➔ Trả về 5
  • string index $s 0 / string index $s end
  • string range $s 0 4: Cắt chuỗi từ index 0 đến 4
  • string match "*Error*" $s: Khớp wildcard
  • string compare -nocase $a $b: Trả về 0 nếu bằng nhau

2. Format & Scan dữ liệu cấu trúc

Format báo cáo và trích xuất số liệu từ dòng log:

puts [format "Slack: %.2f ns" -0.254]
set line "temp=25.5, voltage=3.3"
if {[scan $line "temp=%f, voltage=%f" t v] == 2} {
puts "Nhiệt độ: $t; Điện áp: $v"
}

3. Biểu thức chính quy (Regexp & Regsub)

  • \d: Chữ số (0–9), \w: Từ (a-z, A-Z, 0-9, _), \s: Khoảng trắng.
  • (...): Capture group để trích xuất dữ liệu con ra biến.
  • regsub -all {pattern} $str $replace targetVar: Cờ -all thay thế mọi vị trí khớp (mặc định chỉ thay lần đầu).
regexp {slack.*?([-0-9.]+)} $line -> slack_val

4. Đọc & Ghi File (File I/O)

Các chế độ mở file: r (đọc), w (ghi đè), a (append nối đuôi):

set fid [open "synthesis.log" r]
while {[gets $fid line] >= 0} {
# Xử lý từng dòng cho đến hết file (EOF = -1)
}
close $fid ;# Bắt buộc đóng file sau khi xong

Tích Hợp EDA Tools với Tcl Scripting

1. Các công cụ EDA chuẩn công nghiệp và vai trò

Design Compiler (DC) Hãng: Synopsys Tổng hợp logic (Synthesis)
PrimeTime (PT) Hãng: Synopsys Phân tích STA (Timing)
Innovus / ICC2 Hãng: Cadence / Synopsys Place & Route (PnR)
Vivado Hãng: Xilinx Toàn bộ luồng FPGA Flow

2. Luồng tổng hợp Design Compiler (DC Flow)

  1. Đọc RTL: analyze, elaborate hoặc read_verilog.
  2. Ràng buộc SDC: create_clock, set_input_delay, set_output_delay.
  3. Compile: compile_ultra hoặc compile -map_effort high.
  4. Báo cáo: report_timing, report_area, report_power.
  5. Xuất kết quả: write -format verilog (netlist), write_sdc.
💡 Best practice: Tách các biến cấu hình (DESIGN_NAME, CLK_PERIOD) ra đầu script.

3. Phân tích & Debug vi phạm Timing với PrimeTime

Lọc danh sách đường truyền có vi phạm (slack âm) và duyệt collection:

set paths [get_timing_paths \
-delay_type max \
-slack_lesser_than 0 -max_paths 50]
foreach_in_collection path $paths {
set slack [get_attribute $path slack]
set sp [get_attribute $path startpoint]
puts "$slack : $sp"
}
